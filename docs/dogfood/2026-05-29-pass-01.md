## Environment & method caveats (read before trusting any item)

- **No `.env.local` present.** Only `ANTHROPIC_API_KEY` + `ANTHROPIC_BASE_URL` are set in the shell.
  Supabase / Clerk / Stripe / Resend / Upstash / PostHog are **unconfigured**, so the agent ran as an
  **unauthenticated (anonymous) user**. Consequences:
  - Real auth (`/signup`, `/login`) and the gc/owner **OnboardingModal** could not be exercised end-to-end.
  - Backend-gated surfaces degrade: `/api/v1/projects/*` → **401**, so project **name/header**, Owner Lens,
    server-persisted projects, conversations, and signatures don't load. These are flagged
    **[backend-gated — could not verify locally]**, NOT asserted as product bugs.
  - What *is* fully testable anonymously (and is most of the Killer App): the workflow picker, the 7 stage
    pages, individual workflow clients (localStorage-backed), the persistent chrome (reads in-repo canonical
    constants), the budget page, the DIY cockpit overlay, lane gating via the `bkg-lane` cookie, and the
    ✨ AI FAB ("magic button", `/api/v1/copilot`, which can use the set `ANTHROPIC_API_KEY`).
- **Screenshots** are captured inline in the dogfood session transcript (the preview tool returns images, not
  files). **Every finding lists the exact reproduction route + selector** so anything here is re-observable.
- **Harness caveat (matters for one finding only):** the in-page JS eval environment intermittently reported a
  **zero-width viewport** (`window.innerWidth === 0`). That makes *coordinate-based clicking and geometry/
  hit-testing on `position:fixed` elements* unreliable — which is why the ✨ FAB result (B3) is marked
  **UNVERIFIED / needs a human tap-test**, not graded. It does **not** affect the rest of the report: every
  other finding rests on **screenshots (real rendered pixels)**, **server-HTML `fetch`**, **`localStorage`
  reads**, **`document.cookie`**, or the **accessibility snapshot** — none of which depend on viewport geometry.
- **Lane mapping** (the task's 5 personas → the app's 7 `ProjectRole` lanes; canonical list in
  `src/lib/use-user-lane.ts`): `owner | gc | contractor | teammate | day_hire | specialist | diy`.
  Note up front: **there is no `developer` and no `owner-rep` lane.** Those two personas fall through to
  the `gc` default and, on a project home, to a "Your Lane home is coming" placeholder. (See findings.)

## SEVERITY-GRADED FINDINGS

*Synthesized from the raw log below (raw-log IDs in brackets). The dominant theme across every persona: **the
app's screens are individually beautiful and on-brand, but the numbers don't agree with each other** — the
persistent chrome is hardcoded to the Marin demo and decoupled from the actual project/ledger, and per-screen
"insight" prose is independently hardcoded, so one project tells several contradictory stories at once.*

### 🟥 BLOCKING (data-integrity / can't-complete / persona-locked-out)

   user's own edits.** [B1, B5, B6, P-DEV] Every new/anonymous user sees Marin's *$312K of $1.65M / $1.15M
